# API четвёртой недели

Базовый адрес: http://127.0.0.1:8000/api/v1/. Все операции требуют
Authorization: Token <токен входа>. Формат JSON, пути заканчиваются /.
Миграция: manage.py migrate. Банк: manage.py seed_exercises.
Команда создаёт или обновляет 30 заданий по устойчивым code, повторный запуск
сохраняет идентификаторы и попытки. Старые упражнения без code также доступны
на своём уровне, могут иметь пустые options, topic и explanation.

## Входной тест

GET /placement/ — 10 вопросов с id, title, level, kind, topic, question, options.
Ответы и объяснения до отправки результата отсутствуют.

POST /placement/:

~~~json
{
  "request_id": "611fb829-a92d-4cbe-b835-3ba7181ef860",
  "answers": [
    {"exercise_id": 1, "answer": "is"},
    {"exercise_id": 2, "answer": "кошка"}
  ]
}
~~~

В примере показана структура двух ответов. Запрос должен содержать ровно
по одному ответу на каждый вопрос из GET /placement/, всего 10.
Неизвестные, повторяющиеся и пропущенные вопросы дают 400 без записи результата.

Ответ 201 содержит id, request_id, score, total, level, created_at.
Результат сохраняется, уровень автоматически обновляется в профиле.
Шкала учебной диагностики: 0–1 балл A1, 2–3 A2, 4–5 B1, 6–7 B2, 8–10 C1.
Это ориентировочная оценка по короткому тесту, без стандартизированной
проверки устной речи, аудирования и письма. В statistics.placement находится
последний результат. Пользователь может уточнить уровень через PATCH /profile/.

## Упражнения

GET /exercises/ — упражнения текущего уровня пользователя (по умолчанию A1).
GET /exercises/?kind=grammar или ?kind=vocabulary — фильтр типа.
Неверный kind — 400. Диагностические вопросы в список упражнений не попадают.
Всего в учебном банке 20 тренировочных вопросов, по 4 на уровень.
Поля совпадают с вопросами теста, правильного ответа в выдаче нет.

Порядок: темы с неисправленными ошибками пользователя, затем прочие темы.
Внутри каждой группы непроверенные или ошибочные задания идут перед решёнными.
Для каждой ошибки учитывается последняя попытка соответствующего упражнения.
Подбор использует ошибки в упражнениях. Исправления из ИИ-чата не классифицируются
по темам автоматически.

POST /exercises/{id}/attempts/:

~~~json
{"request_id":"6d536ad8-8866-444e-b06c-9efe0dcaa637","answer":"some"}
~~~

Ответ 201: id, request_id, exercise_id, answer, is_correct, correct_answer,
explanation, created_at. Регистр и лишние пробелы не учитываются.
Допустимо отправить ответ на известное тренировочное упражнение другого уровня.
Проверка локальная, по одному эталонному ответу. Для открытого текста синонимы
не распознаются. Практический сценарий — выбор одного из options.
Неизвестное или диагностическое упражнение — 404. Пустой ответ — 400.

## Словарь

GET /vocabulary/ — только собственные слова с переводами.
POST /vocabulary/:

~~~json
{"word":"tea","translation":"чай"}
~~~

201 — слово создано, 200 — уже существует с таким же переводом.
Регистр английского слова и повторяющиеся пробелы нормализуются.
Повтор слова с другим переводом — 400, изменять нужно через PATCH.
Старые слова, записанные с другим регистром, распознаются при повторном добавлении.

PATCH /vocabulary/{id}/ — поля word и/или translation.
После изменения серия повторений сбрасывается, слово снова готово к повторению.
DELETE /vocabulary/{id}/ — 204, удаляются также связанные повторения.
Чужое или отсутствующее слово — 404.
Ответ слова содержит id, word, translation, next_review, streak.

GET /vocabulary/review/ — карточки, для которых наступил срок повторения,
включая слова без next_review. Поля: id, word, next_review. Перевод скрыт.

POST /vocabulary/{id}/reviews/:

~~~json
{"request_id":"2de52aa4-7c61-462e-a6d4-132c296ab7ce","answer":"чай"}
~~~

Ответ 201: id, request_id, word_id, answer, is_correct, translation, next_review,
created_at. Перевод проверяется с нормализацией регистра и пробелов.
После верного ответа интервалы составляют 1, 3, 7, 14, 30 дней по серии успехов.
После ошибки серия сбрасывается, следующая попытка через час.
Попытка до назначенного срока — 400.

## Повторная доставка запросов

Для теста, попытки упражнения и повторения слова request_id — обязательный UUID.
Создавайте его один раз на действие, например crypto.randomUUID() в React.
При сетевом повторе отправляйте тот же request_id и то же тело.
Повтор вернёт сохранённый результат с HTTP 200, счётчики и сроки не изменятся.
Повтор UUID с другим содержимым — 400. Новый осознанный ответ — новый UUID.
Идентификаторы разделены по пользователям и операциям.
Повтор старого входного теста не перезаписывает более новый уровень профиля.
Запись результата и связанных изменений выполняется в транзакции.
При конкурентной записи SQLite может вернуть временную ошибку блокировки.
Клиент может повторить запрос с тем же UUID.

## Прогресс

GET /statistics/:

~~~json
{
  "level": "A2",
  "attempts": 2,
  "correct": 1,
  "accuracy": 50.0,
  "completed_exercises": 1,
  "by_kind": {"grammar": {"attempts": 2, "correct": 1}},
  "vocabulary_words": 1,
  "words_due": 0,
  "word_reviews": 1,
  "correct_reviews": 1,
  "conversations": 0,
  "user_messages": 0,
  "placement": null
}
~~~

Все показатели только текущего пользователя. accuracy — процент верных попыток
упражнений, 0.0 при отсутствии попыток. completed_exercises — количество разных
упражнений хотя бы с одной верной попыткой. Повторная доставка по UUID не
добавляет попытку, новый ответ с новым UUID добавляет. Входной тест и слова
учитываются отдельно. placement — последний результат теста либо null.
Удалённое слово удаляется и из статистики повторений, которая строится по
оставшимся записям. Это текущие показатели, отдельной дневной серии пока нет.

Код и примеры HTTP проверены локально. Интерфейс для этих API подключает фронтендер.
Платные запросы к модели для операций четвёртой недели не используются.
