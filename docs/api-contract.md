# Контракт API — неделя 2

Версия 0.2.0. Основа: http://127.0.0.1:8000/api/v1/. Формат JSON, UTF-8.
Пути заканчиваются /. Примеры ниже соответствуют реализованным операциям.

## Авторизация

Без токена доступны GET /health/, GET /scenarios/, POST /auth/register/
и POST /auth/login/. Для остальных операций нужен заголовок:

    Authorization: Token <token из ответа входа>
    Content-Type: application/json

Это Token, а не Bearer. Используется TokenAuthentication DRF: один токен
на пользователя, без автоматического истечения срока. Выход отзывает токен,
повторный вход после выхода создаёт новый. Для внешнего развёртывания нужен HTTPS.
Сессия Django admin не заменяет вход в API.

## Регистрация и вход

POST /auth/register/

    {"email":"student@example.com","password":"River!Maple47_Sky"}

Ответ 201:

    {"user":{"id":1,"email":"student@example.com"}}

Сразу создаётся профиль A1, язык en, пустая цель. Для входа после регистрации
нужно вызвать /auth/login/. Пароль не возвращается: сохраняется хеш Django.
Email приводится к нижнему регистру и используется как уникальный username
стандартного User, поэтому его максимальная длина — 150 символов.
Неверный или повторный email, слабый пароль — HTTP 400. Пароль проверяют
стандартные валидаторы Django; максимальная длина — 128 символов.
Подтверждение email и сброс пароля пока не реализованы.

POST /auth/login/ — те же email и password. Регистр букв email не важен.
Ответ 200:

    {"token":"<секретный токен>","user":{"id":1,"email":"student@example.com"}}

Неверный пароль, неизвестный или отключённый пользователь — HTTP 401.
Вход и регистрация имеют общий локальный лимит 20 запросов в минуту на IP;
при превышении — HTTP 429. Для нескольких процессов понадобится общий кэш.

POST /auth/logout/ — тело не требуется; ответ 204 без содержимого.
Переданный токен удаляется из базы.

## Профиль

GET /profile/ — только профиль вошедшего пользователя. Ответ 200:

    {"level":"A1","goal":"","language":"en"}

PATCH /profile/ — частичное изменение:

    {"level":"A2","goal":"Общение в путешествиях"}

Ответ 200 — обновлённый профиль. Допустимые уровни: A1, A2, B1, B2, C1.
Цель — до 200 символов; язык первой версии — только en.
Владелец определяется токеном; user_id передавать не нужно.

## Диалоги

POST /conversations/

    {"scenario_id":1}

Существующий scenario_id нужно получить через /scenarios/. Пример ответа 201:

    {"id":1,"scenario_id":1,"scenario_title":"Кафе","created_at":"2026-11-08T10:00:00+05:00"}

GET /conversations/ — массив только собственных диалогов, новые первыми.
Пагинации пока нет. Неизвестный scenario_id — HTTP 400.
GET /conversations/{id}/ — один собственный диалог в таком же формате.
Чужой или отсутствующий диалог — 404. Владелец назначается сервером.

## Сообщения

POST /conversations/{id}/messages/

    {"content":"Hello!"}

Текст — от 1 до 2000 символов. Строка из пробелов не принимается.
Ответ 201:

    {
      "user_message":{"id":1,"role":"user","content":"Hello!","feedback":{},"created_at":"2026-11-08T10:01:00+05:00"},
      "assistant_message":null,
      "feedback":[]
    }

На второй неделе сохраняется только сообщение пользователя. Роль всегда user;
ИИ не вызывается и токены не расходуются. Поля assistant_message и feedback
оставлены для следующей недели. Пока assistant_message равен null, интерфейс
не должен показывать выдуманный ответ помощника.

GET /conversations/{id}/messages/ — массив сообщений в порядке created_at, затем id:

    [{"id":1,"role":"user","content":"Hello!","feedback":{},"created_at":"2026-11-08T10:01:00+05:00"}]

История хранится в SQLite и доступна после нового входа и перезапуска сервера.
Чтение и запись чужого диалога возвращают 404 без изменения истории.

## Готовые операции первой недели

GET /health/ — проверка сервера и SELECT 1 к SQLite. Пример ответа 200:

    {"status":"ok","service":"linguabot-backend","version":"0.2.0","database":"sqlite","stage":"week-2"}

При ошибке БД — 503. GET /scenarios/ возвращает массив id, slug, title, description.

## Ошибки и следующие недели

400 — ошибки полей, например {"password":["...сообщение валидатора..."]}.
401 — нет авторизации, неверный/отозванный токен или неверные данные входа.
404 — отсутствующий или чужой диалог.
429 — превышен лимит регистрации/входа.
Ошибки доступа используют поле detail. Пароль и токен в ошибках не выводятся.

GET /exercises/, POST /exercises/{id}/attempts/, GET /statistics/ для вошедшего
пользователя остаются HTTP 501 с error.code=not_implemented и planned_week=4.
Без токена — 401. Генерация ответов ИИ и исправления ошибок — неделя 3.
